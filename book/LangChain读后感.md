大语言模型的工作机制
大语言模型的工作机制可以简单概括为：**基于上文预测下一个token**。具体来说，模型会根据输入的文本序列，逐个预测下一个词，直到生成完整的句子或段落。这一过程可以视为一个黑盒操作，输入一个问题，模型通过不断生成下一个词，最终形成一个完整的答案。


大语言模型的整体结构可以分为以下几个关键部分：
① 输入层：接收原始文本输入。
② 分词器（Tokenizer）：将输入文本分割成词或子词（token），以便模型进行处理。
③ Transformer 编码器（Encoder）：对输入的词进行编码，生成词的向量表示。
④ Transformer 解码器（Decoder）：基于编码器的输出，预测下一个词。
⑤ 输出层：生成最终的文本输出。


Transformer 的工作流程
① 输入处理：原始文本通过分词器被分割成一系列的词或子词。
② 编码阶段：Transformer 编码器对每个词进行编码，生成其向量表示，同时捕捉词与词之间的依赖关系。
③ 解码阶段：Transformer 解码器基于编码器的输出，逐个预测下一个词，直到生成完整的文本。


预训练 与 后训练
预训练
 本质是一种知识压缩的过程 模型通过大量的无监督的学习 将全量的知识和语言模式压缩到其参数中 使模型能够在后续的任务中具备较强的泛化能力

后训练
1.后训练 SFT
	SFT（Supervised Fine-Tuning）：SFT是后训练的第一个阶段，主要通过有监督的方式对模型进行微调。在这个阶段，模型会接触到特定任务的数据，并通过这些数据进一步优化模型的性能。SFT可以针对特定任务进行全局微调，也可以进行部分参数的微调。
2.后训练 RL
	RL（Reinforcement Learning）：RL是后训练的第二个阶段，主要在开放环境下通过模型与环境的交互进行训练。在这个阶段，模型会根据反馈信号不断优化自己的行为，从而进一步提升模型的性能和鲁棒性。


数据、语料和微调数据的关系
 1）数据：是一个广泛的概念，指的是所有可以被观测和记录下来的信息，包括文本、语音、图像等多种模态。数据是构建大模型训练的基础
 2）语料：是数据的一个子集，主要对应于预训练阶段。它通常以文本片段的形式存在，不需要标注，用于模型学习海量的知识。
 3）微调数据：也是数据的一个子集，对应于微调阶段。它面向具体任务，形式为有监督数据，也称为指令数据，用于教会模型解决特定问题的范式

大模型推理的基本概念
是什么
	大模型推理是指在模型部署后的运行时态下，模型接收输入（Prompt），通过与模型权重的运算，不断进行下一次预测，最终生成输出的过程。这一过程可以分为输入控制和生成控制两个主要阶段。

输入控制
输入控制主要涉及对用户Query句子的处理，通过Prompt工程引入有效的上下文信息，以优化模型的输入。Prompt工程的核心在于明确任务约束和引入有效的上下文，从而提升模型的推理效果。

生成控制
生成控制主要关注如何提升模型的推理效率和效果，可以分为提速类和提效类两种策略。

数据编排（Data Curriculum）是什么
  数据编排通常以增量预训练的形式出现
数据编排（Data Curriculum），通常也被称为课程学习（Curriculum Learning）在大规模语言模型中的应用，是一种通过精心设计和安排训练数据的顺序、难度或分布，来优化模型训练过程和最终性能的技术策略。它的核心理念借鉴了人类教育中的“循序渐进”原则
让训练 遵循先易后难

3. 常见应用场景
- 预训练阶段：在海量语料中，按照文本长度、可读性、领域相关性等指标对数据进行排序，先喂给模型简单通用的文本。
- 增量预训练：在已有基座模型的基础上，通过编排新数据（如特定领域知识、新技能指令），逐步注入新知识，避免灾难性遗忘。
- 指令微调：先让模型学习简单的问答对，再逐步过渡到复杂的推理、代码生成或多轮对话任务。


传统的大模型训练
往往采用随机批次（Random Batch）的方式，数据混合在一起，模型每次看到的数据难度波动很大。而数据编排则强调顺序性。通常的做法是让模型先学习简单、清晰、高质量的样本，建立起基础的语言理解和表征能力；随着训练的进行，逐渐引入更复杂、噪声更多、逻辑更难的样本。这种由浅入深的过程有助于模型更稳定地收敛，避免在早期被复杂噪声干扰导致训练失败或陷入局部最优。

什么是数清洗
	它指的是从海量、杂乱无章的原始文本中，剔除那些没用的、错误的、重复的或有害的内容，保留高质量、干净的数据供模型学习

具体包括以下几个核心动作：
1. 去重：删掉完全一样或高度相似的重复段落，避免模型死记硬背。
2. 去噪：清理乱码、HTML标签、广告链接、无关符号等非文本垃圾。
3. 过滤低质内容：剔除句子不通顺、逻辑混乱、包含暴力色情或偏见歧视的文本。
4. 语言统一：确保语料主要使用目标语言（如中文），剔除大量非目标语言的混杂片段。

打个比方，如果预训练就像教学生读书，那数据清洗就是老师先把教材里印错的字、无关的涂鸦和盗版内容都删掉，只留下准确、清晰的知识点，这样学生才能学得更扎实、更高效。

预训练阶段主要依赖的是海量无标注的文本语料

预训练阶段的数据通常不需要标注，因为这一阶段主要依靠海量无标签数据来学习语言的一般规律和世界知识。

微调阶段的数据质量要求确实高于预训练阶段。虽然预训练需要数据规模巨大，但微调需要的是高质量、高精度、符合特定任务指令的数据，以引导模型更好地遵循指令或适应特定领域。

微调数据主要用于模型学习如何遵循指令、适应特定任务或领域，而不是学习语言的基本规律。语言的基本规律主要是在预训练阶段通过大规模语料库学到的。

预训练数据的规模通常非常大，达到万亿（Trillion）token级别，这是大模型具备强大泛化能力的基础。

##### 3.1 为什么需要微调

#### 4.什么是LangChain
  大语言模型的编程框架 将大语言模型与其他工具 数据结合 同时弥补大语言模型的短板
  LangChain中的Chain（链） 是一个核心概念，它的主要作用是将多个独立的组件（如提示模板、LLM模型、输出解析器、外部工具等）连接起来，形成一个可复用的工作流，以完成复杂的任务
前提 
链的主要作用
- 模块化复杂流程：将一个复杂的AI应用流程分解为多个可管理的步骤，并通过链将其串联
- 构建可复用工作流：创建标准化的处理流程，可以在不同场景下重复使用，提高开发效率
- 连接多种组件：可以实现多种组合，例如
  - 将 LLM 与提示模板结合
  - 将 LLM 与输出解析器结合，以结构化方式输出结果
  - 将 LLM 与外部数据源结合，用于问答系统
  - 将多个LLM按顺序结合在一起，前一个LLM的输出作为后一个的输入

#### 5.LangChain中的 AIMessage | HumanMessage | SystemMessage 是什么
![LangChain的消息结构](../img/LangChain的消息结构.png)
> SystemMessage（系统消息）
```java
// 角色定位：由开发者或系统设定，用于初始化对话、定义 AI 的行为准则、角色身份或输出格式。
// 典型用途：设定 AI 为“法律助手”、“情感专家”或“代码审查员”，并规定其回答风格（如“请用简洁的列表形式回答”）
// 技术特性：通常作为对话的第一条消息传入，对后续所有回复具有全局引导作用。它不参与多轮对话的动态更新，但影响模型对上下文的理解方向。
```
> HumanMessage（人类消息）
```java
// 角色定位：代表用户输入，是对话的发起者和驱动者。
// 典型用途：用户的提问、指令、反馈或补充信息，例如“如何优化这段 Python 代码？”或“请解释一下这个概念”。
// 技术特性：是触发模型生成响应的直接输入。在多轮对话中，它会与 AIMessage 交替出现，形成完整的对话历史。支持文本、图片、音频等多模态内容（通过 ContentBlock 标准化处理）。
```
> AIMessage（AI 消息）
```java
// 角色定位：代表模型的输出，是系统对人类输入的响应。
// 典型用途：模型生成的答案、建议、代码片段、工具调用请求等。
// 技术特性：不仅包含文本内容，还可能携带元数据（如 token 使用量、模型版本、时间戳）和工具调用信息（tool_calls），用于后续的函数执行或状态管理。在 LangGraph 等高级框架中，AIMessage 是维护对话状态和流程控制的关键节点。
```
