#### 1.什么是Context Engineering(上下文工程)
> 是什么
```java
Context Engineering（上下文工程）是指在大语言模型（LLM）应用中，通过精心构建、优化和管理输入给模型的上下文信息（Context），以引导模型生成更准确、相关且高质量输出的实践过程
上下文工程的核心作用就是提供角色、背景、约束和示例，把模糊的指令变成精准的指令。
```
***
- 没有上下文工程时
```java
假设你只问AI：“把这段文字翻译成英文。
如果没有上下文工程，AI可能会懵，因为它不知道那段文字是什么风格，是法律合同还是小红书文案？它只能凭感觉翻，结果可能很不准确。
```
- 有了上下文工程
```java
但如果你用了上下文工程，你会这样提供信息：

角色设定：你是一个资深的外贸专员。
背景信息：我们要给德国客户发一封邮件，拒绝他们的降价要求，但要保持礼貌，强调我们的产品质量和售后服务优势。
待翻译文本：No way. Our price is final. Quality is best.

这时候，AI就会结合“外贸”、“德国客户”、“礼貌拒绝”这些上下文，翻出一句非常得体且专业的英文，而不是干巴巴的“No”。
```

#### 2.什么是 上下文压缩
> 是什么
```java
上下文压缩（Context Compression）是指在将文本输入大语言模型之前，通过算法或技术手段去除冗余信息、提炼核心语义，从而在保留关键知识的前提下显著减少 Token 数量的过程。
上下文压缩旨在解决大模型上下文窗口有限及长文本处理成本高、易丢失关键信息（“迷失中间”现象）的问题。它不是简单的截断，而是智能地识别并保留对任务至关重要的信息，同时压缩或丢弃低价值内容。
```
> 主要用途
```java
1.降低推理成本与延迟
通过减少输入 Token 数量，直接降低 API 调用费用，并加快模型的响应速度，特别是在处理长篇文档或多轮长对话时效果显著。

2.提升信息检索与问答精度
在 RAG（检索增强生成）场景中，压缩后的上下文能减少噪声干扰，使模型更专注于核心事实，从而减少幻觉，提高回答的相关性和准确性。

3.突破上下文窗口限制
当文档长度超过模型最大上下文窗口时，压缩技术可将长文本浓缩至窗口范围内，使模型能够处理原本无法一次性读取的超长内容。
```
> 常见技术
```java
1.语义摘要：利用模型生成文本的摘要，保留主干逻辑。

2.关键词/关键句提取：识别并保留包含核心实体和事实的句子。

3.向量空间压缩：在向量层面合并相似语义片段，去重并精简。

4.重要性评分过滤：根据与用户问题的相关性对文本片段打分，仅保留高分片段。
```

#### 3.压缩时的注意事项有哪些？大模型什么时候开始压缩？
> 压缩时的注意事项
```java
1.保持语义完整性
压缩的核心是去噪而非删减关键信息。需确保实体（人名、地名、专有名词）、核心论点、因果关系及逻辑链条不被破坏，避免产生“语义漂移”或事实错误。

2.保留上下文关联性
在对话场景或长文档处理中，需保留前文提到的关键指代对象和背景约束，防止模型因信息缺失而产生幻觉或回答偏离主题。

3.平衡压缩率与精度
过度压缩可能导致细节丢失，影响模型推理深度；压缩不足则无法有效降低 Token 成本。需根据任务类型（如简单问答 vs 复杂推理）动态调整压缩阈值。

4.注意格式与结构
若输入包含代码、表格或特定标记语言（如 Markdown、JSON），压缩时需严格保留其语法结构，否则可能导致模型解析失败。
```
> 大模型开始压缩的时机
```java
大模型本身通常不具备在推理过程中自动压缩输入上下文的能力，压缩操作主要发生在预处理阶段或由外部系统触发，具体时机如下：

输入预处理阶段（最常见）
在将文本发送给大模型之前，由应用层或中间件执行压缩。例如在 RAG 系统中，检索到的文档片段在拼接成 Prompt 前，先经过摘要模型或关键词提取算法进行压缩。

上下文窗口即将溢出时
当累积的对话历史或文档长度接近模型最大上下文窗口限制（如 8k、32k、128k Token）时，系统会触发压缩机制。常见策略包括：

滑动窗口压缩：保留最近 N 轮对话，将更早的历史对话压缩为摘要。

重要性过滤：根据相关性评分，丢弃低价值片段。

显式指令触发
当用户或系统明确发出“总结上文”、“压缩内容”等指令时，大模型会生成压缩后的文本，但这属于生成任务而非推理前的输入压缩。

模型内置的注意力机制（隐性压缩）
部分先进模型（如采用 Long Context 优化技术的模型）在内部通过注意力机制（Attention Mechanism）自动聚焦关键 Token，忽略冗余信息。这属于模型内部的“软压缩”，无需外部干预，但用户无法直接控制。总结：实际工程中，压缩多在送入模型前由外部工具链完成，以确保输入的高效性与准确性；模型内部仅通过注意力机制实现隐性的信息聚焦。
```

#### 4.什么是 记忆&摘要
记忆（Memory）与摘要（Summary）是大模型应用架构中突破上下文窗口限制、实现长期状态保持的核心机制，二者通常协同工作以构建有状态的AI系统。
> 记忆（Memory）
```java
记忆是指将历史交互、用户偏好、任务状态等信息持久化存储，使模型具备“长期记忆”能力，避免会话结束后信息丢失 5。根据存储位置和生命周期，主要分为两类：
- 参数化记忆：存储于模型权重中，包含预训练学到的世界知识，访问快但难以定点修改
- 外部记忆（非参数化）：存储于向量数据库、知识图谱或关系型数据库中，以显式离散数据存在，支持无限扩展、可解释性强，通过检索注入上下文
- 工程实现：通常包含信息抽取（决定记什么）、记忆管理（整合更新）、存储（扁平/层级/图结构）和信息检索（按需召回）四个模块
```
***
> 摘要
```java
摘要是记忆系统中的关键压缩组件，旨在解决长历史对话无法全部塞入上下文窗口的问题
核心作用
- 降低Token成本：将大量交互压缩为结构化摘要，显著减少输入量
- 保持连续性：提炼核心事实与状态变化，避免信息堆叠，支持长期对话的连贯性
- 冲突解决：通过理解状态变化（如用户偏好更新），而非机械保存事实，解决新旧记忆冲突
实现方式
- LLM生成：使用大模型将对话块压缩为关键词、标签或高层级摘要
- 分层摘要：构建根节点（章节级）、中间节点（多块文本）和叶节点（原文）的层次化结构，支持多粒度信息整合
- 动态触发：当记忆节点过多或达到特定阈值时，自动触发摘要过程，生成凝练的高层记忆
```
记忆系统负责信息的持久化存储与管理，而摘要则是记忆系统中用于信息压缩、提纯和冲突解决的关键技术手段，二者共同助力AI从“无状态问答”向“有状态协作伙伴”演进 
***
#### 4.Subagent的context是相互隔离的吗
是的，Subagent 的上下文（Context）通常是相互隔离的。这是多智能体（Multi-Agent）架构中的核心设计，主要目的是防止“上下文污染”并突破单一 Agent 的上下文窗口限制
具体机制如下：
```java
1.独立会话窗口：每个 Subagent 拥有自己独立的 message[] 列表或上下文窗口，互不干扰
2.信息过滤与压缩：Subagent 在其独立的上下文中执行探索、工具调用或迭代过程，这些中间过程产生的大量噪声数据不会直接暴露给主 Agent
3.结果回传：Subagent 仅在任务执行完毕后，将最终结论或经过压缩的有效信息返回给主 Agent，主 Agent 据此进行后续决策
```
